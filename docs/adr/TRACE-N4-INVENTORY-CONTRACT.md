# N4 bounded identity contract

Implementation authority is local only. No Preview inventory or maintenance has been performed. Frozen base: 70c75229c8f2013552ff4ec74a39c47a8891c365. PR #21 and its proposal remain unchanged on their own branch; the old proposal cannot authorise deployment of combined N4 code.

The unresolved predicate is exactly `source_url_hash IS NULL AND submitted_url IS NOT NULL AND source_url_identity_issue IS NULL`. Lead-only rows, valid indexed rows and previously deferred invalid/oversize rows are excluded. A malformed URL still counts until classified. This is not the count of all historical candidates. The importer merges at most 51 matching indexed identities with at most 51 globally unresolved identities and refuses a combined result above 50. A source-specific filter on unresolved rows cannot safely eliminate unknown duplicate URLs. N4 preserves that behaviour.

N4-R1 rule for queries:
- Every N4 `ORDER BY` names table columns (`editorial_candidates.id`, `editorial_candidates.source_url_hash`), never an output alias. In SQLite an unqualified `id` binds to a `substr(id,…) AS id` alias first. That prevents the index from providing the order, so every matching row is read and sorted in a temporary B-tree before `LIMIT`.
- CI therefore rejects any temporary B-tree or unindexed scan in candidate statements on the inventory, pre-check and in-batch guard paths.
- The local workerd test rejects provider reads that grow with the backlog.

Inspection uses publisher Access plus the existing signed internal boundary, explicit Preview target attestation, a separate default-disabled inspection flag, at most 25 rows per page and bounded indexed probes. It returns a pending lower bound capped at 51, a selection digest, per-row redacted classification, duplicate observations and separate logical-write/storage-write-unit estimates. A smaller pending backlog alone does not certify package-specific import readiness. Already-indexed existence is an indexed sample, not an unbounded count; deferred/global processed totals remain unknown. No inspection writes a nonce or audit row. Read-only signed replay remains possible during the existing 60-second signature validity; previously spent mutation nonces are refused.

Maintenance has a separate default-disabled flag and an owner-approved profile. It binds the Preview UUID and target attestation, implementation and frozen migration hashes, publisher, canonical finite UTC window, approval reference and at most ten explicit request selections. Each selection binds request UUID, cursor, row limit, selection digest and separate ceilings. There is no automatic pagination or execution. Each request is manually submitted, with a fresh transport nonce. An import approval is never consulted.

The accepted canonical classifier and backfill statements are reused. A guarded plan is composed with the nonce and an attributed audit receipt in one atomic batch. A second full source/lead/state/history snapshot and the mutation-trigger/index certificates are checked inside that batch. Unknown write triggers/indexes, stale selections, conflicting peers, unsupported oversized protected fields and insufficient ceilings fail before mutation. Only the two identity columns are updated. Invalid/oversize URLs retain their original text and receive the accepted issue code.

Existing `admin_audit_log.event_id` uniqueness provides durable request receipts; `admin_request_nonces` supplies transport replay protection. Receipts are insert-only through this endpoint. No schema change is necessary. A fresh-nonce duplicate request returns the original receipt with zero writes; the spent original nonce is refused. Receipt reconciliation stays available through inspection authority when maintenance is closed. Lost or inconsistent accounting is observable and never triggers redispatch.

For n selected rows the precommitted logical-change reservation is n+2 (one audit receipt, one nonce). A conservative index/sequence footprint reserves 5n+8 storage write units, separately from logical changes. The relevant index and trigger catalogues are certified. Actual provider `rows_written` is recorded when available; no local simulation claims a provider-side spending guarantee. The three-item import's separate 40-change allowance is untouched.

Database UUID cannot be introspected through the D1 SQL binding. Runtime target fields are trusted deployment attestation, not independent provider identity discovery. Before activation an independently approved provider/binding inspection must verify the actual UUID and configure the attestation. Client-supplied target fields alone never grant authority.
